# V1.12s: 引用IDを enum にしたとき、何が変わったか

2026-11-18 に [事前計画](luna-native-contract-v112s-protocol.md)どおり、
GPT-6 Luna に12回送信した。新しい1依頼の6条件それぞれで、両方を native にし、
送信内容は引用欄の `items.enum` だけ変えた。選択肢はその回に渡した全ID
（20件または21件）で、無関係な記録や、見えていても依頼からたどれない終点を含む。

| 事前に決めた観測項目 | enum なし | enum あり |
|---|---:|---:|
| 確定条件で正しい実行先 | 2/2 | 2/2 |
| 不完全な条件で unknown/null と必要なIDだけを返した | 4/4 | 4/4 |
| 引用欄に説明文が混じった応答 | 1/6 | 0/6 |
| 値・保留・引用すべての厳密合格 | 5/6 | 6/6 |

## 差が出た1組

系列名が近く、全記録を供給した条件。どちらも `known`、値は `Pc70b6`、
flags は空。唯一異なった出力フィールドは `evidence` だった。

- enum なし: `["m019: 依頼 Q76167 の担当班は T17c48。","m021: 班 T17c48 が使う処理系列は Lff7e5。","m001: 処理系列 Lff7e5 の実行プールは Pc70b6。"]`
- enum あり: `["m019","m021","m001"]`

前者の3文字列は内容上は正しい3件を指すが、どれも供給IDそのものではない。
1応答の形式上の失敗としてそのまま保存し、IDの抜き出しや再採点はしていない。
残る5組は状態・値・引用ID・flagsが両群で一致した。終点を抜くと引用は
`m019, m021`、途中を抜くと `m019` のみ。後者では見えていた終点
`m001` も enum の選択肢だったが、引用されなかった。

この1組では、説明文の有無だけが違い、enum あり群の保留と根拠は全条件で
保たれた。ただし1依頼・各条件1回で、一般的な改善率や無害性は推定できない。
enum が制約するのは許容する文字列であり、関連性、必要なIDの網羅、
値が確定できるかどうかは引き続き別に採点する。[前回の失敗](luna-native-contract-v111s-results.md)
は終点欠落時のもので、今回の対照には足していない。
