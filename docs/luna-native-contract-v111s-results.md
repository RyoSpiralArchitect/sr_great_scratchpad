## どこで失敗したか

値は12/12、出力の構造も12/12正しかった。事前に定めた値と引用の
厳密合格は native 5/6、JSON mode 6/6。両方式とも6/6という
条件は達成しなかった。失敗は主条件ではなく「近い系列ID・終点欠落」の
native の1件で、実際の `evidence` は次のとおり。

```json
["m010: 依頼 Qbd07c の担当班は T181cd。", "m001: 班 T181cd が使う処理系列は L6106a。"]
```

どちらも対象の記録に言及しているが、文字列全体は供給したIDと一致
しない。そのため呼び出し側が拒否した。別の依頼との混同や存在しない
記録の創作とは区別する。採点時にIDを抜き出す補正や再試行はしていない。
同じ入力の JSON mode は正確な2つのIDを返した。

2つの削除条件はともに20レコード。結果は、単なるレコード数ではなく、
この依頼から確認できる範囲に対応した。ただし1つの新規依頼・各条件1回で、
一般的な推論能力、方式間の優劣、検索の有効性を示すものではない。
